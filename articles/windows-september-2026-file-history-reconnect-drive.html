윈도우 업데이트 후 ‘드라이브 다시 연결’, SSD보다 KB5124008부터 확인

9월 Windows 업데이트 뒤 파일 히스토리 백업이 멈췄을 때 KB5124010 적용 여부를 확인하는 방법.

1. 9월 업데이트 뒤 시작됐다면 외장 SSD를 포맷하지 않는다

2026년 9월 8일 Windows 11 보안 업데이트 KB5124008을 설치한 뒤 파일 히스토리가 갑자기 ‘드라이브 다시 연결’을 띄운다면 저장장치 고장부터 의심할 필요는 없다. Microsoft가 이 업데이트의 알려진 문제로 공식 확인한 증상이다. 정상적으로 연결된 백업 드라이브인데도 새 백업을 만들거나 기존 백업을 갱신하지 못할 수 있다. 가장 먼저 설정 > Windows 업데이트 > 업데이트 기록에서 KB5124008 또는 그 이후 9월 업데이트 설치 시점을 확인한다. 증상이 그 직후 시작됐다면 외장 SSD 초기화, 파티션 삭제, 파일 히스토리 기록 제거 같은 조치는 멈추고 최신 수정 업데이트 적용 여부부터 확인한다.

2. 진짜 연결 문제와 업데이트 버그는 세 가지로 구분한다

Microsoft가 공개한 대표 증상은 세 가지다. 1) 호환되는 백업 드라이브가 연결돼 있는데도 ‘드라이브 다시 연결’이 표시된다. 2) 파일 히스토리의 ‘마지막 백업’ 시간이 갱신되지 않는다. 3) 이전에 백업된 파일에 ‘사용 가능한 이전 버전 없음’이 보일 수 있다. 여기에 이벤트 뷰어에서 FileHistory.exe와 KERNELBASE.dll 관련 충돌이 기록되는 경우도 있다. 반대로 파일 탐색기에서도 드라이브가 아예 사라지고 다른 PC에서도 읽히지 않는다면 케이블, 전원, 저장장치 자체 문제를 따로 확인해야 한다. 오류 문구만 보고 모든 외장 드라이브 문제를 KB5124008 탓으로 묶지 않는다.

3. 해결 순서는 KB5124010 이후 업데이트 설치가 먼저다

Microsoft는 이 파일 히스토리 문제를 2026년 9월 22일 이후 릴리스된 업데이트, 예를 들어 KB5124010에서 해결했다고 안내한다. 따라서 1) 설정 > Windows 업데이트를 열고 업데이트 확인, 2) 사용 가능한 최신 누적 업데이트 설치, 3) 재부팅, 4) 제어판 > 시스템 및 보안 > 파일 히스토리에서 백업 상태 확인 순서로 진행한다. KB 번호가 정확히 KB5124010이 아니더라도 그보다 나중에 나온 누적 업데이트에 수정이 포함될 수 있으므로 ‘KB5124010만 찾아서 수동 설치’하는 데 집착할 필요는 없다. 회사 PC라면 업데이트가 관리 정책으로 지연될 수 있어 IT 관리자 확인이 먼저다.

4. 수정 뒤에는 새 백업보다 마지막 백업 시간부터 확인한다

업데이트와 재부팅이 끝났다면 바로 대용량 백업을 새로 만들기 전에 파일 히스토리가 정상 상태로 돌아왔는지 확인한다. 제어판 > 시스템 및 보안 > 파일 히스토리에서 기존 드라이브가 인식되는지 보고, ‘지금 실행’으로 소량의 변경 파일이 실제 백업되는지 확인한다. 이어 ‘마지막 백업’ 시간이 현재 시각에 가깝게 바뀌는지 본다. 파일 탐색기에서 중요한 파일의 이전 버전 기능도 한두 개만 시험한다. 이렇게 작은 범위로 먼저 확인하면 드라이브 포맷이나 백업 세트 삭제 없이 수정 업데이트가 효과가 있었는지 알 수 있다. 백업이 정상화되기 전에는 기존 백업 폴더를 정리하지 않는다.

5. 24H2와 25H2에서 확인할 빌드가 다르다

KB5124008은 Windows 11 버전 24H2와 25H2에 적용되지만 OS 빌드는 다르게 표시된다. 24H2는 26100 계열, 25H2는 26200 계열을 사용한다. 설정 > 시스템 > 정보의 Windows 사양이나 winver에서 버전과 빌드를 먼저 보면 엉뚱한 패키지를 찾는 일을 줄일 수 있다. Microsoft의 9월 22일 KB5124010 안내도 24H2와 25H2용 누적 업데이트로 제공된다. 인터넷에서 다른 버전의 .msu 파일을 받아 억지로 설치하기보다 Windows 업데이트가 제시하는 패키지를 우선한다. 특히 조직에서 관리하는 PC는 수동 설치가 정책과 충돌할 수 있으므로 관리자가 승인한 경로를 따른다.

6. 업데이트가 안 보이면 드라이브를 건드리기 전에 버전부터 확인한다

Windows 업데이트에서 KB5124010이나 그 이후 수정이 보이지 않는다면 먼저 업데이트 일시 중지가 켜져 있는지, 재부팅 대기 중인 업데이트가 있는지, 현재 Windows 11 버전이 무엇인지 확인한다. 24H2 Home과 Pro는 2026년 10월 지원 종료가 예정돼 있어 최신 버전으로 이동하라는 안내가 함께 보일 수 있다. 이 상황에서 파일 히스토리 오류를 해결하겠다고 디스크 관리에서 볼륨을 삭제하거나 exFAT·NTFS로 다시 포맷하면 기존 백업까지 잃을 수 있다. 저장장치가 파일 탐색기에서 정상적으로 열리고 다른 파일 복사도 된다면 수정 업데이트 확보가 우선이다. 필요한 경우 Microsoft 업데이트 기록에서 해당 버전의 최신 누적 업데이트를 확인한다.

7. 하면 안 되는 실수는 백업이 깨졌다고 원본까지 정리하는 것이다

파일 히스토리 화면에 오류가 떠도 기존 백업 데이터와 원본 파일이 즉시 손상됐다는 뜻은 아니다. 수정 확인 전에는 1) 백업 드라이브 포맷, 2) FileHistory 폴더 수동 삭제, 3) 원본 문서 정리, 4) 레지스트리 청소 도구 실행을 피한다. 특히 ‘사용 가능한 이전 버전 없음’이 보인다는 이유로 백업 파일을 지우면 업데이트 수정 후 복구 가능성을 스스로 없앨 수 있다. 중요한 문서는 파일 히스토리 하나만 믿지 말고 다른 외장 저장장치나 클라우드에도 별도 사본을 둔다. 현재 오류를 고치는 작업과 기존 자료를 보존하는 작업을 분리해야 문제 해결 과정에서 추가 손실을 막을 수 있다.

8. 최신 업데이트 뒤에도 실패하면 로그와 드라이브 상태를 함께 본다

9월 22일 이후 수정이 포함된 최신 업데이트를 설치하고 재부팅했는데도 백업이 실패하면 그때부터 Windows 자체 문제와 저장장치 문제를 나눈다. 제어판 > 시스템 및 보안 > 파일 히스토리에서 오류 문구를 기록하고, 이벤트 뷰어의 응용 프로그램 로그에서 FileHistory.exe 관련 오류 시각을 확인한다. 외장 드라이브는 다른 USB 포트나 다른 PC에서 읽기·쓰기 테스트를 하되 포맷은 하지 않는다. 회사나 학교 PC라면 정책으로 파일 히스토리가 제한됐는지도 관리자에게 확인한다. 중요한 자료를 별도 위치에 복사한 뒤 Microsoft 지원에 버전, OS 빌드, 설치된 KB 번호, 오류 문구를 함께 전달하면 원인 범위를 더 정확히 좁힐 수 있다.
